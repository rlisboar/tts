### #241 — `_tts_live` lê `self._worker` DUAS vezes: `close()` no meio estoura AttributeError
2026-10-01 ~03:1x local · repo tts-rod · achado do gate #229 (família #207/#228 — mesma classe: close() concorrente no meio do ciclo de vida do worker)

CÓDIGO ANTES (live_pipeline.py, `_tts_live`):

    if self._worker is None:
        self._worker = _LiveWorker(voice_id=self.voice_id)   # atribuição
    if self._worker.ativo:                                    # 2ª LEITURA

`close()` na thread do WS entre a atribuição e a 2ª leitura zera a referência
(`self._worker = None` no `close()`, linha 249) e a linha seguinte estoura
`AttributeError: 'NoneType' object has no attribute 'ativo'` no MEIO do turno — em
vez de o TTS cair para o in-process. Não deixa processo órfão (o filho nem chegou a
subir; quem sobe é o `start()` do pre-warm, já coberto pelo #207/#228): a exceção é
o dano.

cai no in-process, que o worker criado no meio é FECHADO e que `_worker` volta a None.

── FIX (nome local, mesmo padrão do `w` do #207/#228)
    w = self._worker
    if w is None:
        w = self._worker = _LiveWorker(voice_id=self.voice_id)
    if w.ativo: ...   # e `w.gerar(...)` / `w.fecha()` logo abaixo

O turno anda com `w`; o `close()` que cai no meio pode zerar `self._worker` à vontade.
Com o worker já fechado, `w.ativo` é False e o turno cai no in-process SEM marcar
`_worker_indisponivel` (não inventa estado de fallback para uma sessão que está indo
embora). O ramo `except` segue marcando a sessão quando o `gerar` falha.
